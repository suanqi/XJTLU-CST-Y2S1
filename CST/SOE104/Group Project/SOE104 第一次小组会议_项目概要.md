## 二、项目是什么

设定在 1848 年：**用 Java 代码控制一支马车队**，从 0 英里走到 2,000 英里，限 120 回合。不靠人手操作——代码就是决策者。

- 以**面向对象**方式设计队伍：旅行者的角色、行为、全队策略、出发补给。
- 引擎给所有队伍运行**相同的 3 个随机种子**——成绩只取决于代码质量，不取决于运气。
- 练习重点：**继承、多态、接口、封装、组合**，通过构建一个决策 AI 在河流、风暴、车轴断裂和饥饿中活下来。

## 三、游戏核心规则

### 3.1 资源

| 资源             | 说明                                       |
| -------------- | ---------------------------------------- |
| Food 食物        | 每回合消耗：口粮 × 存活人数 + 2 × 牛的数量；用完很危险         |
| Oxen 牛         | 马车的引擎：4+ 头 = 全速，越少越慢，0 头 = 抛锚；牛每回合吃 2 食物 |
| Spare parts 零件 | 修车时消耗                                    |
| Ammo 弹药        | 打猎的入场券（HUNT 每次耗 1 发）                     |
| Money 金钱       | 付渡船费、躲避匪徒、交易站买卖                          |
| Health 健康      | 每人 0–100，0 = 死亡                          |

### 3.2 出发采购（General Store）

- 每队相同钱包：**$2,000**（恰好等于经典购物篮价格 + $300 零钱）。
- 价格：食物 $2、弹药 $3、零件 $30、牛 $80。买多少自己定。
- 经典配置：500 food + 80 ammo + 5 oxen + 2 parts + $300 现金（不采购时的默认方案，只是其中一个选项，不是推荐）。
- 马车最多装 **500 食物**，多余的全部腐烂。

### 3.3 每回合流程（固定 7 步）

strategy 决策 → 前进 → 吃饭 → 随机事件 → 每名成员行动 → 结算 → 存活检查

### 3.4 饥饿惩罚

吃不上饭时全体掉血，连续饥饿逐回合加重：**5、8、12、17、之后每回合 23**；饥饿期间 HEAL 和 REST 无效；吃饱一顿即重置。

### 3.5 六种成员动作（每人每回合一个，效果由引擎固定决定）

| 动作     | 效果                                 |
| ------ | ---------------------------------- |
| HUNT   | 耗 1 弹药 → +7 食物（Hunter 为 10）        |
| HEAL   | 自己 +10 血（Doctor 改为治疗全队血最少者 +15）    |
| REST   | 自己 +3 血                            |
| SCOUT  | 本回合 +3 英里（Scout 为 +6）              |
| MOVE   | +5 英里，**执行者** −1 血（含 Driver）       |
| DEFEND | 若本回合有威胁事件，全员 +3 血（每回合只触发一次，一人防守即可） |

### 3.6 随机事件

- 每回合触发概率约 15% → 43%（随进度上升），严重度 1–10（随进度上升）。
- 9 种事件：RIVER（河流）、STORM（风暴）、BREAKDOWN（故障）、ILLNESS（疾病）、ATTACK（袭击）、TRADER（交易站）、HUNT_OPP（狩猎机会）、BAD_TRAIL（岔路）、THEFT（偷窃）。
- 每次用三种姿态之一应对：**SAFE**（稳妥，通常花钱/物资）、**RISKY**（赌博，可能大赚可能受伤甚至死牛）、**AVOID**（绕行，通常损失里程）。
- 所有事件的完整数值表公开在 Engine Rules Spec——**策略可以胜过骰子**。
- 公平规则：付不起钱的 SAFE 选项（渡船 $25、逃匪 $30）会自动降级为 AVOID。

### 3.7 策略指令（Directive）

| 维度 | 选项 |
| --- | --- |
| 速度 Pace | SLOW 12 / NORMAL 20 / GRUELING 28 英里（满牛时）；GRUELING 全员 −4 血、15% 概率死一头牛 |
| 口粮 Rations | BARE 1（全员每回合 −1 血）/ MEAGER 2 / FULL 5（吃饱全员 +2 血） |

不提供策略时引擎默认 NORMAL + FULL——一个很耗食物的默认，认真做策略会更好。

### 3.8 交易站（TRADER）

- 除钱以外所有货物可买卖；买入价随市场波动：**×0.7（便宜）/ ×1.0（正常）/ ×1.4（贵）**；卖出价 = 买入价 × 70%。
- 每次访问限一笔交易；单种货物每次最多买 50 单位；可砍价（haggle，成功概率 0.2–0.9）。

## 四、需要实现什么

### 4.1 必做：PartyFactory（唯一入口）

- createMembers()：**必须返回 3–5 个成员**，否则直接判失败。
- buySupplies()（可选）：返回 null = 引擎买经典购物篮。
- strategy()（可选）：返回 null = 引擎默认 NORMAL/FULL。
- resolver()（可选）：返回 null = 永远 SAFE。

### 4.2 必做：成员与角色

成员必须继承 Member 抽象类并 override act(Situation)。官方提供 5 个角色类：

| 角色       | 天赋                                      |
| -------- | --------------------------------------- |
| Hunter   | 自己 HUNT 产 10 食物/发（基础 7）                 |
| Doctor   | 自己 HEAL +15 且治疗全队血最少者                   |
| Scout    | 自己 SCOUT +6 英里（基础 +3）                   |
| Mechanic | **光环**：只要活着，修车不消耗零件                     |
| Driver   | **光环**：只要活着，GRUELING 代价减半（−2 血、死牛概率 7%） |

- 可以重复选同一角色（自我天赋各自生效），光环不叠加（一个活着的 Mechanic/Driver 就够）。
- 只能加 private 字段（阈值、历史记忆等）；**public 字段会被 OOP 评分扣分**。
- 也可直接继承 Member 自定义职业（无天赋）。

### 4.3 推荐：shared-context 共享上下文模式

策略、事件处理、成员三处视角不同，官方推荐在工厂里创建一个自己的状态对象分发给所有成员，让全队共享记忆、互相下指令（这是组合的正确用法，也是拿到 OOP 高分的关键）。

## 五、提交要求

- 1 个或多个 .java 文件，或一个只含 .java 的 .zip。
- 最多 **20 个文件**；文件在压缩包根目录；**无 package 声明**；UTF-8；每个文件一个 public 类。
- **恰好一个** PartyFactory 实现；成员 3–5 人。
- **不需要写报告**——平台自动分析取代报告。
- 编译环境 JDK 21，classpath 只有 oregon-api。

## 六、评分标准（全自动，取自最后一次提交）

**总分 = 0.20 × OOP + 0.50 × 游戏结果 + 0.15 × 命名 + 0.15 × 效率**

| 维度 | 分值 | 要点 |
| --- | --- | --- |
| 面向对象设计 OOP | 20 | 清晰的类层次、封装（无 public 字段）、真多态（不用 instanceof）、接口使用、内聚 |
| 游戏结果 Game | 50 | 60% 里程 + 25% 存活率 + 15% 物资（按里程折算），3 个种子取平均 |
| 命名与可读性 | 15 | PascalCase 类名 / camelCase 方法变量，无单字母或含糊命名 |
| 执行效率 | 15 | 平均 ≤8,000 步操作即满分；正常逻辑只有 100–6,000，不用担心 |

**功能门槛**：代码编译失败 / 崩溃 / 超时 → Game 记 0 分，总分封顶 40；使用禁用 API → 直接 0 分。
（评分详情见 How marks are computed.png，与任务书 §5 一致。）

## 七、红线与注意事项

1. **抄袭**：平台跨队伍（含历史）做代码相似度检测。
2. **禁用 API**（字节码扫描，违规 0 分）：反射、Runtime/ProcessBuilder、线程、System.exit、ClassLoader、java.util.Random、直接修改引擎状态、文件/网络访问、读取环境变量。仅 System.out 打印允许；Math.random() 和时间 API 可用（被沙箱改写为确定性）。
3. **预算**：每个回调约 100,000 步操作，超预算该回合被跳过；每个种子 10 秒墙钟。
4. **防御式编程**：act() 绝不能抛异常（含 null action type）——崩溃会把总分封顶在 40。
5. **同伴互评**：个人分数按贡献调整——保留工作记录很重要。

## 八、官方提示（Hints）

- 从官方 **sample 起步**：完整可运行、故意平庸，第一个里程碑就是打败它。
- **replay 是最好的调试器**：每次提交后看回放，每回合的事件、选择、血量、物资一目了然。
- **食物优先**：忽视递增饥饿惩罚是最快的失败方式；尽早 HUNT，留意牛的胃口。
- 商店是你自己的：$2,000 怎么花自己定。
- 常见 0 分陷阱：java.util.Random；文件/网络访问；出现第二个 PartyFactory；act() 抛异常。
- 先提交、后迭代：尽早拿到第一次回放。

## 九、小组需要共同确定的核心设计决策（供会上讨论）

1. 队伍构成与角色搭配（3–5 人怎么配：几个 Hunter/Doctor/Scout，是否带 Mechanic 和 Driver 光环）。
2. 出发采购方案（$2,000 如何分配）。
3. 速度与口粮策略（何时 GRUELING，何时 BARE/MEAGER）。
4. 9 种事件的应对策略表（SAFE / RISKY / AVOID 的选择规则）。
5. 代码架构与模块划分（PartyFactory、角色类、Strategy、Resolver 如何拆解）。
