## 1. 级联计数器 Cascaded Counters

- **级联 Cascading**：一个计数器的输出驱动下一个计数器的输入，以获得**更高模数**的计数。
- **总模数 = 各级模数的乘积**（overall modulus = product of the individual moduli）。

### 1.1 同步 IC 级联（TC → CTEN）
- 计数器 1 的**使能 CTEN 接 HIGH**（始终计数）；
- 计数器 1 的**终值 TC** 接到计数器 2 的**使能 CTEN**：
  1. 起初 TC=LOW，只有计数器 1 计数；
  2. 计数器 1 计到终值 9 → **TC=HIGH**，下一时钟上升沿计数器 2 加 1；
  3. 计数器 1 清零，TC 变回 LOW。

![[EEE104/Note/assets/L17-p05.png|520]]
> ▲ 两个 decade 计数器级联（TC→CTEN，实现模 100）

> 📌 **芯片上的"CTR DIV 10"是什么意思？有用吗？** ✅ 有用——它是芯片符号的**标准功能标注**（IEEE/ANSI 逻辑符号）：
> - **CTR = Counter**（计数器）——说明这块芯片的功能是计数；
> - **DIV 10 = ÷10**（分频 10 / 模 10）——说明它是**十进制（decade）计数器**，模数为 10。
> - 作用：一看就知道每块芯片的**模数** → 级联总模数 = 10 × 10 = **100**（÷100 分频器）；也解释了为什么 TC 在计到 **9** 时有效。
> - 注意：它**不是引脚**，不参与电路动作，只是"说明书"。课件后面还会出现 **CTR DIV 16**（模 16 二进制计数器，见 1.2 节）。

- 用途：更高模数计数；**分频器**（产生更低频率且同步的时钟）。

### 1.2 截断序列 Truncated Sequences ⭐
**方法一 · 译码终态后清零 Decode the terminal count, then clear**：

- **思路**：把计数器译码到"目标模数对应的状态"，用译码输出清零，得到比芯片本身更小的模数（截断序列）。
- **为什么两种芯片的 /SR 类型不一样？** 由**芯片内部清零端类型**决定（回看 [[Lecture 16 同步计数器]] 3.4 节）：
  - 课件这张图选的 **CTR DIV 10**（如 74HC160）：内部 **CLR 是异步清零** → 符号上的 **/SR 是异步输入**；
  - 课件那张图选的 **CTR DIV 16**（如 74HC163）：内部 **CLR 是同步清零** → 符号上的 **/SR 是同步输入**。
  - ⚠️ **"DIV 10 = 异步、DIV 16 = 同步"只是这两颗芯片的搭配，不是"十进制必然异步"！** 十进制也有同步清零型号（74HC162），二进制也有异步清零型号（74HC161）。四兄弟对照：

| 型号 IC | 类型 Type | CLR 清零端 |
|---|---|---|
| 74HC160 | 十进制 decade | **异步** |
| **74HC162** | 十进制 decade | **同步** |
| **74HC161** | 二进制 binary | **异步** |
| 74HC163 | 二进制 binary | 同步 |

  - 符号上怎么看出异步/同步？IEEE 符号规则：**复位标注与时钟"绑定"（如带 C1 前缀，表示沿上清除）= 同步**；**与时钟无关（孤立的 /SR）= 异步**。课件两张图正是用这两种画法区分（并配文字标注）。
- **这个区别带来什么后果？——"该译码哪个状态"不一样！**（⚠️ 与十进制/二进制无关，**只看清零端是异步还是同步**）

| | 异步清零芯片（课件中的 CTR DIV 10，如 74HC160） | 同步清零芯片（课件中的 CTR DIV 16，如 74HC163） |
|---|---|---|
| 清零时机 When reset | 译码输出一有效就**立即清零**，不等时钟 | 译码输出有效后，**下一个时钟沿**才清零 |
| 该译码哪个状态 Decode | **0110（6）**——目标最后状态的后一个 | **0101（5）**——目标最后一个状态本身 |
| 计数序列 Sequence | 0→1→2→3→4→5→(**6 一闪而过**)→0 | 0→1→2→3→4→**5（完整停留一拍）**→0 |
| 模数 Modulus | **6**（÷6）✓ | **6**（÷6）✓ |

- **四种情况用"时钟一格一格走"看清楚**（目标 ÷6，即需要 0–5 共六个完整状态）：

**① 异步清零 + 译码 5（0101）→ ÷5 ❌**

```
时钟沿： ↑1  ↑2  ↑3  ↑4  ↑5  ↑6   ↑7
状态：   0   1   2   3   4   5⚡→0  0 …
                            ↑ 5 刚出现几纳秒就被当场清零，
                              "数不到 5"
```
完整停留过的状态：0,1,2,3,4 = **5 个** → 每 5 拍循环一次 → **÷5** ❌

**② 异步清零 + 译码 6（0110）→ ÷6 ✓**（正确做法）

```
时钟沿： ↑1  ↑2  ↑3  ↑4  ↑5  ↑6  ↑7   ↑8
状态：   0   1   2   3   4   5  (6一闪)  0 …
                            ↑ 6 只当"触发信号"，瞬间被清、不算状态
```
完整停留过的状态：0,1,2,3,4,5 = **6 个** → **÷6** ✓

**③ 同步清零 + 译码 6（0110）→ ÷7 ❌**

```
时钟沿： ↑1  ↑2  ↑3  ↑4  ↑5  ↑6  ↑7  ↑8  ↑9
状态：   0   1   2   3   4   5   6   0 …
                            ↑ 6 要"住满整整一拍"，下一沿才被清
```
完整停留过的状态：0,1,2,3,4,5,6 = **7 个** → **÷7** ❌

**④ 同步清零 + 译码 5（0101）→ ÷6 ✓**（正确做法）

```
时钟沿： ↑1  ↑2  ↑3  ↑4  ↑5  ↑6  ↑7  ↑8
状态：   0   1   2   3   4   5   0 …
                            ↑ 5 住满一拍，下一沿回 0，6 从不出现
```
完整停留过的状态：0,1,2,3,4,5 = **6 个** → **÷6** ✓

- **记忆口诀**：异步清零是"**当场枪毙**"——被译码的状态活不过一纳秒、**不算数**，所以要**多译一格**（译 6）；同步清零是"**缓刑一拍**"——被译码的状态能活满一整拍、**算数**，所以就**译最后一格**（译 5）。
  - 换算式：**异步清零 → 模数 = 译码值**（译 6 → ÷6）；**同步清零 → 模数 = 译码值 + 1**（译 5 → ÷6）。
- 💡 总规律（与 Lecture 15 的 decade 计数器一致）：**异步清零 → 译"目标最后状态 +1"；同步清零 → 译"目标最后状态"本身**。这条规律**与芯片是十进制还是二进制无关，只看清零端类型**——若把课件里的异步清零十进制芯片换成同步清零的 **74HC162**，译码状态同样要从 0110 改成 **0101**。

![[EEE104/Note/assets/L17-p09.png|520]]
> ▲ 课件：译码清零实现截断序列（÷6，CTR DIV 10 异步版）

> 📌 **这张图里的模数到底是 6 还是 10？——两个答案都对，看问的是谁：**
> - **芯片本身（CTR DIV 10）= 模 10**：它天生数 0–9，10 个状态；
> - **整个电路（芯片 + 外接译码清零）= 模 6**：译码门检测到 6（0110）就通过异步 /SR 把计数器拉回 0，芯片**从来没机会数到 9**，实际序列只有 0–5 共 6 个状态。
> - 模数只能"截小"不能"变大"：模 10 芯片可以截成 ÷6，但模 6 芯片没法扩成 ÷10。考试问"这个电路模数多少" → 答 **6**；问"这颗芯片固有模数多少" → 答 **10**。

**方法二 · 终态装载初值 Load an initial count at the terminal count**：
- **÷40,000 计数器**：终值 65,535（16 位最大）时输出 HIGH → 装载初值 **25,536 = 63C0₁₆**。
- $65{,}535 - 25{,}536 + 1 = 40{,}000$（正好 40,000 个状态）。

![[EEE104/Note/assets/L17-p11.png|520]]
> ▲ 装载初值实现 ÷40,000

> 📌 **怎么从图上看出它是 ÷40,000？** 图上看不到"40000"这个数，它是四步"读图"算出来的：
> 1. **数位数**：4 个 4 位计数器级联 = **16 位** → 满模 $2^{16} = 65{,}536$（能数 0–65,535）；
> 2. **看反馈线**：最高位计数器的**终值输出 RCO/TC 接回各级的 LOAD 端**（不是清零端！）——这是"装载法"的标志：数到 65,535 时 RCO=1，下一个时钟沿把预置值装进去；
> 3. **读预置值**：各级数据输入端 D 上固定的 0/1 组合 = **63C0₁₆ = 25,536**；
> 4. **套公式**：$\text{模数} = 65{,}535 - 25{,}536 + 1 = \mathbf{40{,}000}$（+1 是因为首尾两个状态都算进循环）。
> - 工作循环：25,536 → 25,537 → … → 65,535 →（装载）→ 25,536，一圈正好 **40,000 拍** → ÷40,000。
> - **装载法 vs 清零法**：清零法需要外接译码门"认出"目标数再清零；装载法直接利用芯片**自带的 RCO** 触发装载，**不需要外接译码电路**，所以大模数（如 40,000）用装载法更省事。

## 2. 计数器译码 Counter Decoding

- **译码**：判断计数序列中**某个状态是否出现**（如译码状态 6 = 110 → 与门接 $Q_2Q_1\bar Q_0$）。

![[EEE104/Note/assets/L17-p12.png|500]]
> ▲ 译码状态 6（110）的与门接法

- **毛刺问题 Glitches**：**异步计数器**的传播延迟产生**过渡状态（transitional states）** → 译码输出出现**毛刺 glitch**。
- **解决方法**：在过渡状态结束后再**选通（strobe/gate）**译码输出。
