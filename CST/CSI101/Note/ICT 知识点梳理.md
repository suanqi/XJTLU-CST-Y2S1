## 一、Week 1 · 计算机系统导论 Introduction to Computer Systems

### 1.1 三大组成 Three components
| 组成 | 含义 | 特点 |
|---|---|---|
| **Hardware 硬件** | 可触摸的物理机器：处理器、内存、存储、外设 | 快，但只会做极简单的操作 |
| **Software 软件** | 指挥硬件的指令：系统软件（OS、驱动）+ 应用软件 | 把简单操作组合成有用的工作 |
| **Data 数据** | 被处理的对象 | 与程序一样以二进制存放，**本身无意义直到被解释** |

> 三者缺一不可（Remove any one and there is no system——只有零件，不是系统）。

### 1.2 系统的层次 Hierarchy of systems
计算机是**分层**构建的：每一层**隐藏下一层的复杂性**，向上提供更简单的接口（interface）。
> 例：写 C 代码的人不用关心晶体管；写汇编的人不用关心微指令。每层只跟相邻层打交道。

### 1.3 输入-处理-输出模型 Input-Process-Output model
- Input data → Process → Output data，全程由**存储程序（stored program）**控制；
- **同一台机器能做不同的事，靠的是换程序**——这就是通用计算机的本质。

### 1.4 机器指令 Machine instructions
- 每条指令本质是一个**二进制模式**；汇编语言给它人类可读的名字。同一指令三种等价视图：
  - 二进制 `1000 1001 1101 1000` = 十六进制 `89 D8` = 汇编 `MOV EAX, EBX`
  - （十六进制是二进制的"速记"：**4 位二进制 = 1 位十六进制**，`1001 1000 = 0x98`）
- 每个 CPU 有自己的指令集（约 100–200 条），**对特定机器固定、不能扩展**；不同 CPU 指令集相似但不标准。
- **指令分四类**（记住类别 + 例子）：
  1. **I/O**：`IN`、`OUT`
  2. **数据传输与运算**：`MOV`、`ADD`、`MUL`、`AND`、`OR`
  3. **程序控制转移**：`JMP`、`JC`、`CALL`、`RET`
  4. **机器控制**：`HLT`（停机）、`INT`（中断）、`NOP`（空操作）

### 1.5 冯·诺依曼模型 von Neumann model（1945 EDVAC 报告）
| 要点 | 详细说明 |
|---|---|
| 程序 = 指令列表 | 一步步指挥机器完成任务 |
| **程序与数据共享同一内存** | 都存成二进制，不加区分 |
| 内存可改写 | 换任务只需换内存内容，不用重造机器 → **通用性** |
| 处理器是主动部分 | 按顺序取指执行（除非跳转改变 PC） |
| **瓶颈 bottleneck** | 指令和数据**共用同一条通路**（总线），CPU 大部分时间在等内存；**缓存、更宽总线、预取**都是为了缓解它 |

> 助记：冯·诺依曼 = 「**一**台机器、**一**个内存、**一**条通路」，换程序就换工作，代价是这条通路成了瓶颈。

### 1.6 哈佛架构 Harvard architecture
- 程序与数据**物理分离**、各有一条总线 → **取指令和取数据可以同时进行**（吞吐更高）；
- 典型用于 DSP（数字信号处理器）和 PIC/AVR 微控制器；
- 现代处理器 = **modified Harvard**：主存统一，但**指令缓存与数据缓存分开**（吸取两种架构的优点）。

### 1.7 硬件与软件的接口
- 硬件与软件必须**兼容**（interface 一致）：指令集就是它们之间的"合同"；
- 例：1978 年为 Intel 8086 编译的程序，今天仍能在 x86 处理器上运行——**向后兼容**。

### 1.8 数字逻辑与 VHDL（了解）
- 硬件可用 **VHDL**（硬件描述语言）描述：设计可以先**仿真测试**再制造（错误便宜时先改）；
- 描述自动喂给综合与布局工具生成最终电路。

## 二、Week 2 · 处理器 Processors

### 2.1 CPU 五大组件 Five key components
| 组件 | 干什么 | 补充 |
|---|---|---|
| **Control unit 控制单元** | 理解每条指令，告诉其它组件该做什么；沿控制总线在正确时刻发控制信号 | CPU 的"指挥" |
| **ALU 算术逻辑单元** | 算术：+ − × ÷、inc/dec；逻辑：比较（等于/小于/大于）、位运算 AND/OR/NOT/XOR | 结果常放入"累加器" |
| **Clock 时钟** | 以固定节拍同步所有组件；频率单位 Hz | **1 GHz = 每秒 10⁹ 个周期** |
| **Buses 总线** | 地址总线（单向，CPU→内存）、数据总线（双向）、控制总线（双向） | 见 2.4 |
| **Registers 寄存器** | CPU 内部极小的快速存储 | 只有寄存器能"存"，其余四个负责动/算/决策/同步 |

### 2.2 五个概念寄存器 Five registers（取指-译码-执行用）
| 寄存器 | 全称 | 作用 |
|---|---|---|
| PC | program counter | 存**下一条**指令的地址，随执行递增 |
| MAR | memory address register | 存**正要访问**的内存地址 |
| MDR | memory data register | 存**刚从内存取回**的数据 |
| CIR | current instruction register | 存**正在执行**的指令 |
| Acc | accumulator | 暂存运算结果 |

> **寄存器 vs 内存**：寄存器在 CPU **内部**、只有几十个、访问 <1 ns；内存在主板上、上亿单元、50–100 ns（约慢百倍）。

> **❓ 为什么这里不是 EAX、EBX、ECX？**（易混淆点）
> 这是**两套不同层次的寄存器**：
> - 本节的 PC/MAR/MDR/CIR/Acc 是 **CPU 内部概念模型**的寄存器（L02 讲「指令如何被执行」时用）；
> - 3.2 节的 **EAX/EBX/ECX/EDX/ESI/EDI/EBP/ESP** 是 **x86 程序员可见**的通用寄存器（L03–04 写汇编时用）。
> - 对应关系：**PC 在 x86 上的真名是 EIP**（指令指针）；**Acc 的角色由 EAX 承担**；而 **MAR、MDR、CIR 是芯片内部硬件寄存器，程序员看不见也写不了**。
> - 考试：L02 考 PC/MAR/MDR/CIR 概念；L03–04 考 EAX/EBX 等编程寄存器。

### 2.3 取指-译码-执行循环 Fetch-Decode-Execute cycle（机器周期）
**四步，每步做什么要能按顺序默写：**
1. **Fetch 取指**：PC 的值 → **MAR** → 经地址总线到内存 → 指令经数据总线 → **MDR** → 复制进 **CIR**；然后 **PC 递增**指向下一条。
2. **Decode 译码**：控制单元把 CIR 拆成 **opcode（操作码：做什么）+ operand（操作数：对谁做）**，并准备好控制信号。
3. **Execute 执行**：ALU 计算 / 数据移动 / 跳转（改 PC）。
4. **Store（write-back 写回）**：结果写回累加器或内存，并**更新状态标志**（零/负/溢出——这就是 if 语句能工作的基础）。

> **例题（讲义"adding two numbers"完整走查）**：内存 100 号存 12、101 号存 30；程序在地址 0 起：`LOAD 100`、`ADD 101`、`STORE 102`。
> ① PC=0：取指 LOAD 100 → 译码 → 执行：Acc = 12；PC=1
> ② PC=1：取指 ADD 101 → 执行：Acc = 12+30 = 42；PC=2
> ③ PC=2：取指 STORE 102 → 执行：内存 102 号 = 42
> ④ 结束：地址 102 里存着 42。

> **频率**：3 GHz = 每秒 30 亿周期；一条简单指令可能占**多个**周期；现代 CPU 一个周期可完成**多条**指令（流水线/多发射）。

### 2.4 总线 Buses（方向要记清）
| 总线 | 方向 | 传什么 |
|---|---|---|
| 地址总线 address bus | **单向**：CPU → 内存 | 要访问的地址 |
| 数据总线 data bus | **双向** | 指令或数据 |
| 控制总线 control bus | **双向** | 控制信号（读/写/时序） |

> **地址宽度 → 寻址空间（高频计算）**：n 位地址总线 → 最多 2ⁿ 个单元。
> 16 位 → 2¹⁶ = 65,536 ≈ **64 KB**；32 位 → 2³² ≈ **4 GB**；64 位 → 2⁶⁴（天文数字）。

### 2.5 性能六因素（"时钟频率不是全部"）
| 因素 | 说明 |
|---|---|
| 时钟频率 clock speed | 每秒周期数；5 GHz 附近后难以继续提升 |
| 核心数 cores | 多核并行；多核 SoC 是手机/平板的主流 |
| 缓存 cache | 见下表；**缓存常常比多 1 GHz 更值钱** |
| 字长与总线宽度 | 一次处理/传输的位数 |
| 流水线 pipelining | 指令重叠执行（取指/译码/执行流水线） |
| 指令集设计 ISA | CISC vs RISC（见 2.6） |

**缓存层次（访问代价表）**：L1（每核 32–64 KB，约 4 周期）→ L2（约 12 周期）→ L3（多核共享，约 40 周期）→ **RAM 约 200 周期**（差两个数量级！）。
**现代处理器技术**：SMT/超线程（一个物理核伪装成两个逻辑处理器）、分支预测（猜跳转方向）、乱序执行（不等上一条完成就执行下一条）。

### 2.6 CISC vs RISC
| | CISC（复杂指令集） | RISC（精简指令集） |
|---|---|---|
| 代表 | x86（Intel/AMD） | ARM（手机/平板） |
| 特点 | 单条指令做更多事，指令长短不一 | 指令简单（LW/ADD/SW）、定长、低功耗 |
| 权衡 | 代码短但译码复杂 | 代码长但流水线好做、省电 |

### 2.7 数据表示 Data representation（进制基础）
| 单位 | 大小 |
|---|---|
| bit | 0/1 |
| byte | 8 bits（0~255） |
| kilobyte | 10³ bytes（L02 十进制口径；**L08 讲二进制前缀 1 KB = 2¹⁰ = 1024 B**，两讲口径不同，按各自讲义记） |
| megabyte | 10⁶ bytes |
| gigabyte | 10⁹ bytes |
| terabyte | 10¹² bytes |

- **十六进制是二进制的速记**：4 位二进制 = 1 位十六进制（0–9、A–F）；
- **二进制 → 十进制**：位权求和；**十进制 → 二进制**：除 2 取余（第一个余数是 LSB）。
- > 例：101₁₀ → 101÷2=50 r1 → 50÷2=25 r0 → 25÷2=12 r1 → 12÷2=6 r0 → 6÷2=3 r0 → 3÷2=1 r1 → 1÷2=0 r1 ⇒ **1100101₂** ✓
- **补码**（先预习）：负数按"取反+1"存储（详见 Week 6）。

## 三、Week 3–4 · 汇编编程 Assembly Programming（ICT 重头戏！）

### 3.1 环境：MSVC 内联汇编 inline assembly
1. VS2022 新建 **Console App (C++)** 项目；
2. 工具栏 **Solution Platforms 改为 x86**（默认 x64 下 `_asm` 直接报错 **C4235**：`_asm` 只存在于 32 位 x86）；
3. 顶部 `#include <cstdio>`（printf/scanf_s 的来源）；
4. **Ctrl+F5** 运行（不带调试器，控制台窗口保持打开）。
- **数据全部由 C++ 声明**：`_asm` 块内**不能**用 DB/DW/DD 定义数据；汇编里直接写 C++ 变量名/函数名/标签。
- 注释用 `;`（汇编风格）或 `//`（推荐，避免宏里分号出问题）；指令**不区分大小写**（MOV/mov/Mov 一样），但**变量名区分大小写**。

### 3.2 通用寄存器 General-purpose registers（每个都要背熟）
| 寄存器 | 角色 | 能不能随便用？ |
|---|---|---|
| **EAX** | 累加器：运算主力、函数返回值 | ✅ 随便用 |
| **EBX** | 基址/通用 | ⚠️ 用前 push、用完 pop |
| **ECX** | 计数器（`loop` 自动用它） | ✅ 随便用 |
| **EDX** | 乘除扩展、余数、第二个返回值 | ✅ 随便用 |
| **ESI / EDI** | 源/目的索引（数组遍历） | ⚠️ 用前 push、用完 pop |
| **EBP** | 栈帧基址 | ❌ **绝不能动** |
| **ESP** | 栈顶指针 | ❌ **绝不能动** |

- **拆分**：32 位 EAX → 低 16 位 **AX** → 再拆 **AH（高 8 位）/ AL（低 8 位）**。⚠️ 写 AL 只改低字节、高 3 字节不动——大小混用是经典 bug 源。

**EFLAGS 状态标志（if/循环的全部基础，必考）**：
| 标志 | 何时置 1 | 配合的跳转 |
|---|---|---|
| **ZF 零标志** | 运算结果 = 0 | JE / JNE（JZ / JNZ） |
| **SF 符号标志** | 结果的最高位 = 1（有符号角度看是负数） | JS / JNS |
| **CF 进位标志** | 无符号结果放不下（超出 MSB 的进位/借位） | JC / JNC；无符号比较 JA/JB |
| **OF 溢出标志** | **有符号**结果放不下（两同号数相加得异号） | JO / JNO；有符号比较 JG/JL |

> `cmp a, b` 内部做 **a − b** 只留标志：a=b → ZF=1（je 跳）；a>b（有符号）→ JG 跳；a>b（无符号）→ JA 跳。**比较方向记牢：第一个操作数"减"第二个**。

### 3.3 指令格式与操作数
- **Intel 语法**：`指令 目的, 来源`，数据从右往左流（`mov eax, ebx` = eax ← ebx）。
- 操作数三类：**寄存器 / 立即数 / 内存**；⚠️ **两个操作数不能都是内存**（`mov [a], [b]` 非法，必须经寄存器中转）。
- 大小：BYTE(8) / WORD(16) / DWORD(32)；歧义时显式写 `DWORD PTR [esi]`。

### 3.4 寻址方式五种（配实例，必考）
| 方式 | 写法 | 含义 |
|---|---|---|
| 立即数 | `mov eax, 42` | 直接把 42 放进 eax |
| 寄存器 | `mov eax, ebx` | 复制寄存器 |
| 直接 | `mov eax, total` | 取变量 total 的**内容** |
| 寄存器间接 | `mov eax, [esi]` | 取 esi 所指**地址处**的内容 |
| 基址+位移 | `mov eax, [esi+8]` | 取 [esi+8] 处的内容（结构体/数组用） |
| 变址比例 | `mov eax, [esi+ecx*4]` | 数组第 ecx 个 int（比例只允许 1/2/4/8） |
| 完整 | `mov eax, [esi+ecx*4+8]` | 基址 + 索引×比例 + 位移 |

> **LEA vs MOV（高频考点）**：`lea ebx, myarray` 取的是**地址**；`mov eax, myarray` 取的是**内容**。printf/scanf_s 要地址 → 用 lea。
> 例：`int myarray[5]` 假设首地址 0x1234，`mov eax, myarray` → eax = 2（myarray[0] 的值）；`lea ebx, myarray` → ebx = 0x1234。

### 3.5 栈 The stack
- 栈向**低地址**生长；**ESP 永远指向栈顶**。
- **PUSH x** = 先 ESP−4，再写入 [ESP]=x；**POP x** = 先读 x=[ESP]，再 ESP+4。
- 例（ESP 初始 0x1000）：`push eax` → ESP=0x0FFC、[0x0FFC]=eax；`pop ebx` → ebx=[0x0FFC]、ESP=0x1000。
- **CALL** = push 返回地址 + 跳转；**RET** = pop 返回地址 + 跳回。

### 3.6 指令全解（每条都要会写）
**数据移动**：
- `mov` 复制；`xchg a,b` 一条指令交换两个操作数；
- `push/pop` 压栈/弹栈；
- `movzx`（零扩展：无符号数转大）、`movsx`（符号扩展：有符号数转大）；
- `lea` 取地址。

**算术**：
- `add` / `sub`（结果存第一个操作数）；
- `inc`（+1，**不改 CF**）/ `dec`（−1）；
- `neg`（取负 = 补码取反+1）；
- `imul` 有符号乘；**除法三件套（必背）**：
```asm
mov eax, dividend    ; 被除数进 eax
cdq                  ; 有符号：eax 符号扩展到 edx（无符号除法则用 xor edx, edx）
idiv divisor         ; edx:eax ÷ 除数 → 商在 eax、余数在 edx
```
> 例：17 ÷ 3：`mov eax,17` → `cdq` → `idiv ecx(3)` ⇒ eax=5、edx=2。
> ⚠️ `cdq` = Convert Doubleword to Quadword：把 EAX 的符号位复制填满 EDX；不写它，EDX 里的垃圾会让商错得离谱。**有符号用 cdq、无符号用 xor edx,edx**，别配错。

**逻辑与移位**：
- `and/or/xor/not` 位运算；**`xor eax, eax` = 清零惯用法**（比 mov eax,0 更短，反汇编最常见）；
- `test a,b` = 与运算**只留标志**（测位用：`test edx,1` + `jnz` 判断奇数；测零用 `test eax,eax` + `jz`）；
- `shl`（左移 = ×2）、`shr`（**逻辑**右移，高位补 0）、`sar`（**算术**右移，复制符号位）、`rol/ror` 循环移位。
> **SHR vs SAR 经典例子**：−32 = 0xFFFFFFE0。`shr 2` → 0x3FFFFFF8 = 1073741816（**错！**符号位丢了）；`sar 2` → 0xFFFFFFF8 = −8（对，÷4）。**负数右移必须 SAR**。

**跳转家族完整表（必背）**：
| 判断 | 有符号（int） | 无符号 |
|---|---|---|
| 大于 | JG | JA |
| 大于等于 | JGE | JAE |
| 小于 | JL | JB |
| 小于等于 | JLE | JBE |
| 相等 / 不等 | JE / JNE（两家族共用） | |
| 其它 | JMP 无条件；JS/JNS 看 SF；JC/JNC 看 CF；JO 看 OF | |

### 3.7 控制流模板（三件套，默写级）
**① if-else**：
```asm
    mov   eax, a
    cmp   eax, b
    jg    bigger          ; a > b ?
    ; ...else 分支...
    jmp   done
bigger:
    ; ...then 分支...
done:                     ; 标签后必须跟指令！
```
**② 计数循环（LOOP）**：
```asm
    mov   ecx, 10
again:
    ; ...循环体...
    loop  again           ; = dec ecx + jnz again
```
**③ 条件循环（测顶部）**：
```asm
    mov   esi, 0
check:
    cmp   esi, limit
    jge   finish
    inc   esi
    jmp   check
finish:
```
> **LOOP 两个陷阱**：① ECX=0 进入 → 先 dec 变成 4,294,967,295 → **循环约 42 亿次**（进入前先测零）；② LOOP 是**短跳转**（目标 128 字节内），循环体太长会编译报错。
> **LOOP 与 INC 都不改标志**——所以 `shr`（留 CF）之后可以安全接 `jnc`、`inc`、`loop`。
> **嵌套循环**：内外层都想用 ECX → 内层前 `push ecx`、内层后 `pop ecx` 保存外层计数。

### 3.8 函数与调用约定 Calling conventions（必考大题）
**三个约定**：
| 约定 | 谁清栈 | 特点 |
|---|---|---|
| **__cdecl** | **调用方**（`add esp, 4×n`） | C++ 默认；printf 必须用它（参数个数可变） |
| __stdcall | 被调方（`ret n`） | Windows API |
| __fastcall | 调用方 | 前两个参数走 ECX/EDX |

**手写调用七步**（以 `absDiff(10, 3)` 为例逐步走查）：
```asm
; --- 调用方 ---
push  3              ; ① 最后一个参数先压
push  10             ; ② 第一个参数后压（右→左！10 更靠近栈顶）
call  absDiff        ; ③ CALL 自动压返回地址并跳转
add   esp, 8         ; ⑤ 返回后调用方清栈：2 个参数 = 8 字节
mov   answer, eax    ; ⑥ 结果从 EAX 取回
```
**被调方内部（栈帧）**：
```asm
int absDiff(int a, int b)
{
    int result;
    _asm {
        push  ebx          ; EBX 是"必须保存"寄存器 → 先压
        mov   eax, a       ; a 在 [ebp+8]
        mov   ebx, b       ; b 在 [ebp+12]
        sub   eax, ebx     ; eax = a-b（顺便留下标志！）
        jns   done         ; SF=0 → 已 ≥0，跳过取负
        neg   eax          ; 否则取负
done:
        mov   result, eax  ; 局部变量在 [ebp-4]
        pop   ebx          ; 还原（每条路径都要 pop！）
    }
    return result;         ; 返回值放 EAX
}
```
**栈帧布局（CALL 之后）**：
```
[ebp+12]  b（第二个参数）
[ebp+8]   a（第一个参数）
[ebp+4]   返回地址
[ebp]     旧 EBP        ← EBP 指向这里
[ebp-4]   局部变量
```
> **为什么右→左压参**：最后压的第一个参数恰好落在栈顶附近 [ebp+8]——被调方按固定偏移找参数。
> **返回值**：EAX（64 位结果用 EDX:EAX）。
> **寄存器保护规则**：EAX/ECX/EDX 随便用；**EBX/ESI/EDI 用完必须还原**（push/pop）；EBP/ESP 不能碰。忘了还原 → 程序在 `_asm` 块**外**崩溃。

### 3.9 调用 C 库函数（printf / scanf_s）
**printf（输出）**——参数右→左、按"值"传：
```asm
mov   eax, value
push  eax              ; ② 第二个参数（值）先压
lea   eax, msg
push  eax              ; ① 第一个参数（格式串**地址**）后压
call  printf
add   esp, 8           ; 2 个参数 × 4 字节
```
**scanf_s（输入）**——变量参数必须传**地址**（lea，不是 mov！）：
```asm
lea   eax, first       ; scanf_s 要写入变量 → 传地址
push  eax
lea   eax, format
push  eax
call  scanf_s
add   esp, 8
```
> 口诀：printf 传**值**，scanf_s 传**地址**；调用完 `add esp, 4×参数个数`。

## 四、Week 5 · 高级语言与编译器 HLL & Compilers

### 4.1 语言的三个层次
| 层次 | 特点 | 例子 |
|---|---|---|
| **HLL 高级语言** | 人易读、可移植（跨平台标准）、各有擅长领域 | C/C++（系统）、Java（Web/移动）、Python（AI） |
| **汇编** | 机器指令的可读名，**与 CPU 家族绑定**（x86 汇编不能在 ARM 上跑） | `pushl %ebp`（Intel）vs `mflr 0`（POWER） |
| **机器码** | 二进制，CPU 直接执行 | `1011110101010001…` |

- **符号 tokens**：词与标点；**语法 grammar**：组词成合法语句的规则；**语义 semantics**：解释语句含义。
- 程序语言**严谨、无歧义**（自然语言常有歧义："Fair is foul, and foul is fair"）。

### 4.2 三种翻译器（对比必考）
| 翻译器 | 干什么 | 时机 | 代表 |
|---|---|---|---|
| **编译器 compiler** | 把 HLL **整体**翻译成机器码 | 运行**前**，一次性 | C/C++ |
| **汇编器 assembler** | 把汇编指令翻译成机器码 | 运行前 | — |
| **解释器 interpreter** | **逐句**翻译并**立即执行** | 运行时，交错进行 | Python |

- **C 流程**：源 → 编译 → 汇编 → 目标码 → **链接/装入** → 执行；
- **Java 流程**：源 → 编译成 **byte code（字节码）** → **JVM** 解释执行——**解释器也被称为虚拟机**（byte code 是虚拟机的"机器码"）。
- 解释器什么时候更好：需要交互/调试、代码要跨平台立即运行、代码只跑一次。

### 4.3 链接器 Linker
- 编译器能把单个模块翻成二进制，但**不能解析对其它模块的引用**（外部函数仍是符号）；
- **链接器把各模块的目标代码与库合并成一个可执行文件**，并解析这些外部引用。
- **库文件必须链接进程序才能用**（True）。

### 4.4 算法与程序
- **算法**：解决良定义问题的**逐步方法**，**与语言无关**（可用自然语言/伪代码描述）；**程序** = 算法的语言相关实现。
- 开发流程：问题 → 算法 → 选语言 → 写程序 → 编译 → 调试运行。

### 4.5 代码复用三种方式
1. **宏库**（源码级）：预处理展开成源代码；
2. **可重定位目标库**：预编译成目标码，链接时合并；
3. **动态库**：内存中共享（多个程序共用一份）。

## 五、Week 6 · 二进制算术 Binary Arithmetic

### 5.1 无符号整数与范围
- n 位无符号：0 ~ 2ⁿ−1。4 位：0–15（0000~1111）；8 位：0–255（0x00~0xFF）。

### 5.2 BCD（8421 码）
- **每个十进制位单独用 4 位二进制表示**：68₁₀ → 0110 1000（BCD），而不是 100 0100（真二进制）。
- 一字节可存 0–99；**ASCII 数字字符的低 4 位正好是它的 BCD**（'5' 的 ASCII = 0110101，BCD = 0101）→ BCD 与字符互相转换容易，但存储浪费、运算麻烦（用于键盘、显示等）。
- **BCD 加法 +6 修正**：某 4 位组结果 **≥10 或产生进位**（非法），该组 **+0110** 修正。
> 例：45+27：0100 0101 + 0010 0111 = 0110 1100 → 低组 1100（12 非法）→ +0110 = 1 0010 → 本组 0010 进位 1；高组 0100+0010+1 = 0111 ⇒ **0111 0010 = 72** ✓

### 5.3 三种负数表示（对比表必背）
| | 负数的表示 | 零的个数 | 硬件 | 运算特点 |
|---|---|---|---|---|
| **符号-数值 sign-and-magnitude** | 最高位取反 | **2 个**（+0/−0） | 需加法器+减法器+比较器 | 加法要分"同号加、异号减"，复杂 |
| **反码 one's complement** | 各位取反 | 2 个 | 只要加法器 | 有进位要**绕回（end-around carry）** |
| **补码 two's complement** | 各位取反**+1** | **1 个** | 只要加法器 | 直接加、丢最终进位；唯一现代标准 |

> 反码加法的**循环进位**例（4 位）：(−2) + (+3) = 1101 + 0011 = 1 0000 → 把进位绕回：0000+1 = 0001（+1）✓

### 5.4 补码详解（最重点）
- **负数 = 正数的"取反+1"**：−25 = ~(00011001) + 1 = 11100110 + 1 = **11100111**；再取一次补码回到 +25（**补码的补码是原数**）。
- **权重法读值**：MSB 的权重是**负的**。$1011 = -8 + 0 + 2 + 1 = -5$。
- **符号扩展**：左侧补符号位、值不变——正数补 0（011 = 00011 = +3），负数补 1（110 = 11110 = −2）。
- **范围**：n 位 = $[-2^{n-1},\ 2^{n-1}-1]$。8 位：−128 ~ +127；32 位：−2,147,483,648 ~ 2,147,483,647。

### 5.5 补码运算
- **加法**：直接加，**丢弃最终进位**。
> 例：+5 + (−5)：00000101 + 11111011 = 1 00000000 → 丢进位 → 00000000 = 0 ✓
- **减法**：A − B = A + (−B)（把减数取补码再相加）。
> 例：9 − 5 = 9 + (−5)：00001001 + 11111011 = 1 00000100 → 4 ✓
- **溢出判定**：**两操作数同号，且结果异号** → 溢出；正+负**永不**溢出。
> 例：+7 + +1 = 0111 + 0001 = 1000（−8）❌ 溢出（4 位正数最大 +7）；−8 + −1 = 1000 + 1111 = 1 0111 → 0111（+7）❌ 溢出。
- **乘法**（部分积法）：按正数算幅值乘积 → 符号位 0 → 若两数异号，对结果取补码。例：+83 × −59 = −4897。
- **除法**：反复减——余数为正 → 商+1 继续；余数为 0 → 商+1 结束；余数为负 → 结束；商的符号由被除数与除数符号决定。

### 5.6 浮点数与 IEEE 754（含编码例题）
- **定点数问题**：小数点位置固定 → 表示范围窄（5.07×10³⁰ 与 9.86×10⁻³² 需 207 位定点）。
- **规格化 normalisation**：二进制下小数点前恒为 1（10.1×2⁵ → 1.01×2⁶）。
- **单精度格式**：`s(1) | exponent(8) | fraction(23)`；指数用 **excess-127**（真实指数 = 存储值 − 127，1~254 有效，0 和 255 保留）；尾数**隐藏前导 1**（hidden bit）。

> **编码例题 ①**：把 −6.5 编成单精度。
> ① 6.5 = 110.1₂ = 1.101 × 2²
> ② s = 1（负）；真实指数 2 → 存储 = 2+127 = 129 = 1000 0001
> ③ 尾数：1.101 去隐藏 1 → 101 0000 0000 0000 0000 0000
> ⇒ `1 10000001 10100000000000000000000` = **0xC0D00000**

> **编码例题 ②**：0.75 = 0.11₂ = 1.1 × 2⁻¹ → s=0，指数 −1+127 = 126 = 0111 1110，尾数 1000…0 ⇒ **0x3F400000**。

- **特殊值**：
| 情况 | 值 |
|---|---|
| 指数、尾数全 0 | **零（±0）** |
| 指数全 0 + 尾数非 0 | **非规格化数**（真实指数按 −126，无前导 1） |
| 指数全 1 + 尾数全 0 | **±∞** |
| 指数全 1 + 尾数非 0 | **NaN**（√(−1)、∞/∞、∞+(−∞)） |
- float 范围约 1.2×10⁻³⁸ ~ 3.4×10³⁸；⚠️ 范围内**不是所有数都能表示**（连部分整数都不行）。

## 六、Week 8 · RAM 与内存层次 RAM & Memory Hierarchy

### 6.1 主存的角色
- 冯·诺依曼机器中，主存是 CPU **唯一的工作区**：CPU 只能操作主存里的数据；输入设备把数据写进来、输出设备从里面读。
- 两个重要性质：① 主存是**计算机内部**的物理存储；② CPU **只能**处理主存内的数据。

### 6.2 字节寻址与地址
- 最小单位是 bit，但**按字节访问更高效** → **内存是字节寻址（byte-addressable）**：一个地址指向 8 位。
- **地址宽度决定最大内存**：由 CPU 地址寄存器位数和地址总线位数决定。
| 地址宽度 | 最大内存 |
|---|---|
| 8 位 | 2⁸ = 256 B |
| 16 位 | 2¹⁶ = **64 KB** |
| 32 位 | 2³² = **4 GB** |
| 64 位 | 2⁶⁴（天文数字，>170 亿 GB） |

### 6.3 端序 Endianness（必考）
- 多字节整数有两种存放方式。以 **0x12345678** 存进内存为例：
| 地址 | Little endian（x86） | Big endian |
|---|---|---|
| 低地址 | **78**（LSB 在低地址） | 12（MSB 在低地址） |
| ↓ | 56 | 34 |
| ↓ | 34 | 56 |
| 高地址 | 12 | 78 |
- **Little endian**：读符号/大小写转换容易（跨宽度读写方便）；**Big endian**：与人类书写顺序一致、看字符串直观。
- x86 = **little endian**。

### 6.4 单位（L08 二进制口径）
- 1 B = 8 bit；**1 KB = 2¹⁰ = 1024 B；1 MB = 1024 KB；1 GB = 1024 MB**（基于 2¹⁰ 的二进制前缀，对应二进制寻址的本质）。⚠️ 与 L02 的十进制口径（TB = 10¹²）不同，按各讲记。

### 6.5 SRAM vs DRAM（对比表必背）
| | DRAM | SRAM |
|---|---|---|
| 存储单元 | **电容 + 晶体管**（1 个晶体管） | **6 管触发器** |
| 刷新 | **需要**定期刷新（约每 64 ms） | 不需要 |
| 速度 | 慢 | 快 |
| 密度/成本 | 高密度、便宜 | 低密度、贵 |
| 用途 | **主存** | **缓存** |
| 共同点 | **都易失**（断电丢数据） | |

- 内存指标：**延迟 latency**（ns，从请求到第一个数据的时间）与**带宽 bandwidth**（GB/s，总吞吐量）。

### 6.6 ROM 家族与固件
- ROM **非易失**（断电保留）：Mask ROM（出厂固化，不可改）→ EPROM（紫外线擦除）→ **EEPROM / Flash**（电擦除；Flash 是特殊 EEPROM）。
- **固件 firmware** = "硬件的软件"；**BIOS/UEFI 存在 ROM/Flash 里**——因为开机瞬间主存是空的（易失），CPU 需要一个硬编码的起始地址来执行引导程序。

### 6.7 内存层次 Memory hierarchy（四趋势）
越往下（离 CPU 越远）：**容量越大、访问时间越长、被 CPU 访问频率越低、单位成本越低**。
> 层次：寄存器 → L1/L2/L3 缓存 → RAM（DRAM）→ 磁盘/SSD。

## 七、Week 9 · Cache、磁盘与虚拟内存（L09 ✅）

### 7.1 缓存 Cache

**目的**：把一部分数据放在**离 CPU 更近**的地方以加速访问。缓存远小于主存，但访问时间只是主存的零头。
**按内容访问**：主存按**地址**访问；缓存按**内容**访问，故称 **content addressable memory（内容可寻址存储器）**。

**局部性原理 Localisation of Memory Access**（缓存能工作的根本）：
- **时间局部性 Temporal locality**：最近用过的数据，马上很可能再用（循环、重复调用）；
- **空间局部性 Spatial locality**：刚用过的数据附近的数据，马上很可能被用（数组、顺序代码）；
- 成因：程序员把相关数据聚成数组/记录、程序中的循环、编译器对代码的优化排布。
> 局部性差的例子：`myarray[0]`、`myarray[100000]`、`myarray[200000]` 这样大步跳跃访问大数组（对比顺序访问 `[0]`、`[1]`、`[2]`）。**局部性差时缓存反而降低性能**。

**缓存块的字段**：
- **tag 标签**：区分映射到同一缓存块的不同内存块；
- **valid bit 有效位**：该缓存块是否正在使用；
- **offset 偏移**：指向块内所需的数据。

**直接映射 Direct mapped cache**：N 个缓存块时，内存块 X 映射到缓存块 **Y = X mod N**。
> 例：10 个缓存块时，缓存块 7 只能装内存块 7、17、27、37…（相距 N 的块共享同一缓存块，会发生替换）。

**替换策略 Replacement policy**：
| 策略 | 做法 | 特点 |
|---|---|---|
| Optimal（最优） | 淘汰**未来最久不被使用**的块 | 需预知未来——只能当**基准 benchmark** |
| **LRU**（最近最少使用） | 淘汰**最久没被访问**的块 | 效果好但复杂（要维护每块访问历史，拖慢缓存） |
| **FIFO**（先进先出） | 淘汰**在缓存里待得最久**的块 | 简单常用 |
| Random（随机） | 随机选块替换 | 可能误伤常用块，但**永远不会 thrash**（抖动） |

**写策略 Write policy**（缓存被改、主存未改时的处理）：
- **Write-through（写直达）**：每次写**同时更新缓存和主存**（简单，但每次写都要访问主存）；
- **Write-back（写回）**：更新暂缓，直到**脏块 dirty block** 被替换时才写回主存（快，但要 dirty 位）。

**结构**：
- **Unified（统一缓存）**：指令和数据共用一个缓存；**Harvard cache**：指令缓存与数据缓存分开（局部性更好，复杂度更高）——即 L01 讲的 modified Harvard。
- **多级缓存**：L1（8–64 KB，在处理器上，约 4 ns）→ L2（64 KB–2 MB，在主板或处理器上，15–20 ns）→ … → RAM。
- **Inclusive（包含式）**：小缓存的数据保证也在下一级（可多级同时存在）；**Exclusive（独占式）**：数据只允许存在一份。权衡：访问时间 vs 存储空间 vs 电路复杂度。

### 7.2 磁盘 Disk（大容量存储 Mass Storage）

**特性**：与主存不同，**断电后数据仍然保留**（非易失）。
**种类**：HDD 机械硬盘、SSD 固态硬盘、光盘（CD-ROM、DVD）、U 盘等。

**HDD 结构**：
- 多个**盘片 platters**，两面记录信息；
- 每面 **500–2000 条磁道 tracks**；每磁道 **32–128 个扇区 sectors**；
- **扇区 sector = 最小读写单位**；
- 相同位置的磁道组成**柱面 cylinder**。

**寻址方式**：**CHS**（柱面-磁头-扇区）或 **LBA**（扇区的绝对编号，Logical Block Addressing）——CHS 可映射到 LBA。

**读写四步**：① 确定地址（CHS 或 LBA）→ ② **寻道 seek**（磁臂移到目标磁道上方）→ ③ **旋转延迟 rotational latency**（等目标扇区转到磁头下方）→ ④ **传输 transfer**（读写该扇区）。

**访问时间公式（必考计算）**：
$$\text{Access time} = \text{queue} + \text{seek} + \text{rotational} + \text{transfer} + \text{overhead}$$

> **例题（讲义原题）**：磁盘空闲（queue = 0），overhead = 2 ms，平均寻道 12 ms，转速 7200 RPM，传输 8 KB，传输率 4 MB/s。求平均扇区访问时间。
> - 平均旋转延迟 = 半圈时间 = $\dfrac{0.5}{7200/60}=0.5/120\,\mathrm{s}=4.17\,\mathrm{ms}$
> - 传输时间 = $8\,\mathrm{KB}\ /\ 4\,\mathrm{MB/s}=0.002\,\mathrm{s}=2\,\mathrm{ms}$
> - 总时间 = 12 + 4.17 + 2 + 2 = **20.17 ms ≈ 20.2 ms**

**SSD（固态硬盘）**：由 **NAND Flash** 构建（电擦除、非易失、浮栅晶体管 trapped charge）；**无机械部件**；随机读延迟 **0.1 ms**（HDD 约 5–10 ms）；吞吐 **~500 MB/s**（HDD 80–100 MB/s）；每 GB 价格约为 HDD 的 **4–6 倍**。

**磁盘缓存 Disk cache**：用一部分主存做缓冲区临时存放磁盘数据——写操作**聚批**执行；刚写出的数据可能马上再被读，从缓存里取远快于从磁盘取。（Java `flush()` 即强制写回。）

**读与写**：把文件从磁盘装入 RAM = **reading**（加载程序、打开文件）；把 RAM 数据复制到外存 = **writing**。

### 7.3 虚拟内存 Virtual Memory
- 思想与缓存**相反**：**用低层存储器（硬盘）来"扩充"高层存储器（主存）**——把数据和代码溢写到磁盘上，相当于扩展了主存；
- 磁盘上为此保留的区域叫 **swap area（交换区）**；
- 例：物理内存上限 4 GB，虚拟内存上限 8 GB；
- RAM 不够时把暂时不用的数据换出到磁盘，需要时再调入——**灵活性提升，但比直接访问 RAM 慢**。

### 7.4 云存储 Cloud Storage（了解）
- 数据存在不属于你的数据中心，经网络访问；背后是海量磁盘阵列，数据跨盘/机架/地域**多副本**；
- 每 GB 最便宜、延迟高且不稳定 → 用缓存和 CDN 改善；适合备份、归档、大数据、静态内容。

### 7.5 L09 讲义自测题
1. 用 Cache、RAM、Disk 组成合理的内存层次（性价比）→ **Cache → RAM → Disk**。
2. 「时间局部性：最近用过的数据更可能再次被访问。」T / F？→ **T**。
3. 保存到哪类设备，关机后数据仍保留？→ **外存（secondary storage）**。
4. 磁盘上封闭的同心圆环称为？→ **tracks（磁道）**。
