# W2 · 处理器 Processors

> 讲义：CSI101-L02 ｜ 返回：[[00 期末复习总览]]

---

## 1. CPU 五大组件 Five key components ⭐

| 组件 | 职责 | 补充 |
|---|---|---|
| **Control unit 控制单元** | 理解每条指令，指挥其它组件；沿控制总线在正确时刻发控制信号 | "大脑" |
| **ALU 算术逻辑单元** | 算术：+ − × ÷、inc/dec；逻辑：比较（=、<、>）、AND/OR/NOT/XOR | "计算器"；结果常入累加器 |
| **Clock 时钟** | 以固定节拍同步各组件，频率单位 Hz | 1 GHz = 每秒 10⁹ 周期 |
| **Buses 总线** | 地址/数据/控制三类 | 见第 4 节 |
| **Registers 寄存器** | CPU 内部极小的快速存储 | 唯一"存"的组件 |

> 记忆句：Only the registers store anything. The other four move, decide, calculate or synchronise.

## 2. 五个概念寄存器 Five registers（FDE 循环用）⭐

| 寄存器 | 全称 | 作用 |
|---|---|---|
| **PC** | program counter | 存**下一条**指令的地址，自动递增 |
| **MAR** | memory address register | 存**正要访问**的内存地址 |
| **MDR** | memory data register | 存**刚从内存取回**的数据 |
| **CIR** | current instruction register | 存**正在执行**的指令 |
| **Acc** | accumulator | 暂存运算结果 |

**寄存器 vs 内存**：寄存器在 CPU **内部**、几十个、访问 <1 ns；内存在主板上、上亿单元、50–100 ns（约慢百倍）。

> **❓ 为什么不是 EAX/EBX/ECX？**——两套寄存器不同层次：
> - 本节的 PC/MAR/MDR/CIR/Acc 是 **CPU 内部概念模型**（讲"指令如何被执行"）；
> - EAX/EBX/… 是 **x86 程序员可见**寄存器（W3–4 写汇编用）；
> - 对应：**PC 在 x86 的真名是 EIP**；**Acc 角色由 EAX 承担**；MAR/MDR/CIR 是芯片内部硬件，程序员看不见写不了。

## 3. 取指-译码-执行循环 Fetch-Decode-Execute cycle ⭐

**四步，顺序与寄存器流向要能默写：**

1. **Fetch 取指**：PC 的值 → **MAR** → 经地址总线到内存 → 指令经数据总线 → **MDR** → 复制进 **CIR** → **PC 递增**。
2. **Decode 译码**：控制单元把 CIR 拆成 **opcode（做什么）+ operand（对谁做）**，准备控制信号。
3. **Execute 执行**：ALU 计算 / 数据移动 / 跳转（改 PC）。
4. **Store 写回**：结果写回累加器或内存，**更新状态标志**（零/负/溢出——if 语句的基础）。

### 3.1 例题：完整走查（讲义"adding two numbers"）
内存 100 号存 12、101 号存 30；程序从地址 0 起：`LOAD 100`、`ADD 101`、`STORE 102`。

| 步 | PC | 动作 | 结果 |
|---|---|---|---|
| 1 | 0 | 取指 LOAD 100 → 译码 → 执行 | Acc = 12；PC → 1 |
| 2 | 1 | 取指 ADD 101 → 执行 | Acc = 12+30 = 42；PC → 2 |
| 3 | 2 | 取指 STORE 102 → 执行 | 内存 102 号 = 42 |

### 3.2 频率
- **3 GHz = 每秒 30 亿个时钟周期**；
- 一条简单指令可能占**多个**周期；现代 CPU 一个周期可能完成**多条**（流水线/多发射）。

## 4. 总线 Buses ⭐

| 总线 | 方向 | 传什么 |
|---|---|---|
| 地址总线 address bus | **单向**：CPU → 内存 | 要访问的地址 |
| 数据总线 data bus | **双向** | 指令或数据 |
| 控制总线 control bus | **双向** | 控制信号（读写、时序） |

**地址宽度 → 寻址空间（高频计算）**：n 位地址总线 → 2ⁿ 个单元。
- 16 位 → 2¹⁶ = 65,536 ≈ **64 KB**；32 位 → 2³² ≈ **4 GB**；64 位 → 2⁶⁴（天文数字）。

## 5. 性能六因素（时钟频率不是全部）⭐

| 因素 | 说明 |
|---|---|
| 时钟频率 clock speed | 每秒周期数；约 5 GHz 后难以继续提升 |
| 核心数 cores | 多核并行；多核 SoC 是主流 |
| 缓存 cache | **缓存往往比多加 1 GHz 更值钱** |
| 字长与总线宽度 | 一次处理/传输的位数 |
| 流水线 pipelining | 指令重叠执行 |
| 指令集设计 ISA | CISC vs RISC |

### 5.1 缓存层次（访问代价表，必背数量级）
| 层 | 大小 | 位置 | 访问代价 |
|---|---|---|---|
| L1 | 每核 32–64 KB | 处理器上 | ~4 周期 |
| L2 | — | 处理器上 | ~12 周期 |
| L3 | 多核共享 | 处理器上 | ~40 周期 |
| RAM | — | 主板 | **~200 周期**（差两个数量级！） |

### 5.2 现代处理器技术
- **SMT / 超线程**：一个物理核伪装成两个逻辑处理器；
- **分支预测 branch prediction**：猜条件跳转方向；
- **乱序执行 out-of-order execution**：不等上一条完成就执行下一条。

## 6. CISC vs RISC ⭐

| | CISC | RISC |
|---|---|---|
| 全称 | Complex Instruction Set Computer | Reduced Instruction Set Computer |
| 代表 | **x86**（Intel/AMD） | **ARM**（手机/平板） |
| 指令 | 单条做更多事、长短不一 | 简单（LW/ADD/SW）、定长 |
| 特点 | 代码短，译码复杂 | 流水线好做、**低功耗** |

## 7. 数据表示 Data representation ⭐

### 7.1 单位表
| 单位 | 大小 |
|---|---|
| bit | 0/1 |
| byte | 8 bits（0–255） |
| kilobyte KB | 10³ B（L02 十进制口径；L08 改用 2¹⁰=1024，两讲口径不同，各按讲义记） |
| megabyte MB | 10⁶ B |
| gigabyte GB | 10⁹ B |
| terabyte TB | 10¹² B |

### 7.2 进制转换
- **二进制 → 十进制**：位权求和；
- **十进制 → 二进制**：除 2 取余（**第一个余数是 LSB**）。
> 例：101₁₀ → 101÷2=50 r1 → 50÷2=25 r0 → 25÷2=12 r1 → 12÷2=6 r0 → 6÷2=3 r0 → 3÷2=1 r1 → 1÷2=0 r1 ⇒ **1100101₂** ✓
- **十六进制 = 二进制的速记**：4 位一组换成 0–9/A–F。

### 7.3 补码（预习，W6 详讲）
- 负数按「按位取反 + 1」存储；例：−5（4 位）= ~0101 + 1 = 1010 + 1 = **1011**。
- 补码存在的意义：**减法可以变成加法**（硬件只需加法器）。
