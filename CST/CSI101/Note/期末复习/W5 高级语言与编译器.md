## 1. 语言的三个层次 ⭐

| 层次 | 特点 | 例子 |
|---|---|---|
| **HLL 高级语言** | 人易读、高度标准化、**可移植**（跨 CPU 平台） | C/C++（系统）、Java（Web/移动）、Python（AI） |
| **汇编 Assembly** | 机器指令的可读名；**与 CPU 家族绑定**（x86 汇编不能在 ARM 上跑） | Intel `pushl %ebp` vs POWER `mflr 0` |
| **机器码 Machine code** | 二进制，CPU 直接执行 | `1011110101010001…` |

### 1.1 语言的三个要素
- **符号 tokens**：词与标点；
- **语法 grammar（syntax）**：把符号组合成合法语句的规则；
- **语义 semantics**：解释语法正确语句的含义。
- 程序语言**严谨、无歧义**（自然语言常有歧义）。

## 2. 三种翻译器 ⭐（对比必考）

| 翻译器 | 干什么 | 时机 | 代表 |
|---|---|---|---|
| **编译器 compiler** | 把 HLL **整体**翻译成机器码 | 运行**前**一次性 | C/C++ |
| **汇编器 assembler** | 把汇编指令翻译成机器码 | 运行前 | — |
| **解释器 interpreter** | **逐句**翻译并**立即执行** | 运行时交错进行 | Python |

### 2.1 执行链路
- **C**：源 → 编译 → 汇编 → 目标码 → **链接/装入** → 执行；
- **Java**：源 → 编译成 **byte code（字节码）** → **JVM** 解释执行。
  - **解释器被称为虚拟机（virtual machine）**：因为 byte code 就是这台"虚拟机"的机器码。

### 2.2 解释器什么时候更好
- 需要交互式执行/调试、代码要立刻跨平台运行、代码只运行一次的场景。

## 3. 链接器 Linker ⭐

- 编译器能把**单个模块**翻成目标码，但**不能解析对其它模块的引用**（外部函数仍是符号）；
- **链接器**把各模块的目标代码与库**合并成一个可执行文件**，并解析外部引用。
- 判断题：库文件必须被链接进程序才能使用？→ **True**。

## 4. 算法与程序

- **算法 Algorithm**：解决良定义问题的**逐步方法**，**与语言无关**（可用自然语言/伪代码描述）；
- **程序 Program** = 算法在某种语言里的实现；
- 开发流程：问题 → 算法 → 选语言 → 写程序 → 编译 → 调试运行。
- 判断题：「为 Java 设计的算法不能用 C 实现」→ **False**（算法语言无关）。

## 5. 代码复用三种方式 ⭐

| 方式 | 机制 |
|---|---|
| **宏库 macro library** | 源码级：预处理阶段**展开**成源代码 |
| **可重定位目标库 relocatable object library** | 预编译成目标码，**链接**时合并 |
| **动态库 dynamic library** | **内存中共享**（多个程序共用一份） |
