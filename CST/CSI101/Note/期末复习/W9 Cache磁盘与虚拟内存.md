## 1. 缓存 Cache ⭐

### 1.1 目的与原理
- **目的**：把一部分数据放在**离 CPU 更近**的地方以加速访问；缓存远小于主存，但访问时间只是主存的零头。
- **按内容访问**：主存按**地址**访问；缓存按**内容**访问，故称 **content addressable memory（内容可寻址存储器）**。

### 1.2 局部性原理 Localisation of Memory Access（缓存能工作的根本）
| 局部性 | 含义 | 例子 |
|---|---|---|
| **时间局部性 Temporal** | 最近用过的数据很快会**再次**被用 | 循环、重复调用 |
| **空间局部性 Spatial** | 刚用过的数据**附近**的数据很快被用 | 数组、顺序代码 |

- 成因：程序员把相关数据聚成数组/记录；程序中的循环；编译器对代码的优化排布。
- ⚠️ **局部性差时缓存反而降低性能**：例 `myarray[0]`、`myarray[100000]`、`myarray[200000]` 大步跳跃访问大数组（对比顺序访问 `[0]`、`[1]`、`[2]`）。

### 1.3 缓存块的字段
- **tag 标签**：区分映射到同一缓存块的不同内存块；
- **valid bit 有效位**：该缓存块是否正在使用；
- **offset 偏移**：指向块内所需的数据。

### 1.4 直接映射 Direct mapped cache（必考计算）
- N 个缓存块时，内存块 X 映射到缓存块 **Y = X mod N**。
> 例：10 块缓存，缓存块 7 只能装内存块 7、17、27、37…（相距 N 的块共享一块，会发生替换）。
> 再例：16 块缓存，内存块 50 → 50 mod 16 = **2**。

### 1.5 替换策略 Replacement policy
| 策略 | 做法 | 特点 |
|---|---|---|
| Optimal（最优） | 淘汰**未来最久不被使用**的块 | 需预知未来 → 只能当**基准 benchmark** |
| **LRU**（最近最少使用） | 淘汰**最久没被访问**的块 | 效果好但复杂（维护访问历史，拖慢缓存） |
| **FIFO**（先进先出） | 淘汰**在缓存里待得最久**的块 | 简单常用 |
| Random（随机） | 随机替换 | 可能误伤常用块，但**永不 thrash（抖动）** |

### 1.6 写策略 Write policy
- **Write-through（写直达）**：每次写**同时更新缓存和主存**（简单，但每次写都访问主存）；
- **Write-back（写回）**：更新暂缓，**脏块 dirty block 被替换时**才写回（快，需要 dirty 位）。

### 1.7 结构
- **Unified**（指令+数据共用）vs **Harvard cache**（指令缓存与数据缓存分开）——即 modified Harvard；
- **多级缓存**：L1（8–64 KB，处理器上，~4 ns）→ L2（64 KB–2 MB，主板/处理器上，15–20 ns）→ … → RAM；
- **Inclusive**（小缓存数据保证也在下一级）vs **Exclusive**（数据只存一份）——访问时间/存储/复杂度权衡。

## 2. 磁盘 Disk ⭐

### 2.1 特性与种类
- **非易失**（断电保留）；种类：HDD、SSD、光盘、U 盘。

### 2.2 HDD 结构
- 多个**盘片 platters**（两面记录）；每面 **500–2000 条磁道 tracks**；每磁道 **32–128 个扇区 sectors**；
- **扇区 sector = 最小读写单位**；相同位置的磁道组成**柱面 cylinder**。

### 2.3 寻址方式
- **CHS**（Cylinder-Head-Sector，柱面-磁头-扇区）；
- **LBA**（Logical Block Addressing，扇区绝对编号）——CHS 可映射到 LBA。

### 2.4 读写四步与访问时间公式（必考计算）
**四步**：确定地址 → **寻道 seek**（磁臂移到目标磁道）→ **旋转延迟 rotational latency**（等扇区转到磁头下）→ **传输 transfer**（读写扇区）。

$$\text{Access time} = \text{queue} + \text{seek} + \text{rotational} + \text{transfer} + \text{overhead}$$

> **例题（讲义原题）**：磁盘空闲（queue=0）、overhead=2 ms、平均寻道 12 ms、7200 RPM、传输 8 KB、传输率 4 MB/s。
> - 平均旋转延迟 = 半圈时间 = $\dfrac{0.5}{7200/60}=0.5/120\,\mathrm{s}=4.17\,\mathrm{ms}$
> - 传输时间 = $8\,\mathrm{KB}\ /\ 4\,\mathrm{MB/s}=2\,\mathrm{ms}$
> - 总时间 = 12 + 4.17 + 2 + 2 = **20.17 ms ≈ 20.2 ms**

### 2.5 SSD 对比 HDD
| | HDD | SSD |
|---|---|---|
| 介质 | 磁盘+磁头（机械） | **NAND Flash**（无机械部件） |
| 随机读延迟 | 5–10 ms | **0.1 ms** |
| 吞吐 | 80–100 MB/s | **~500 MB/s** |
| 每 GB 成本 | 便宜 | 贵 **4–6 倍** |

### 2.6 磁盘缓存 Disk cache
- 用一部分主存做缓冲区：写操作**聚批**执行；刚写的数据可能马上被读（从缓存取快得多）。（Java `flush()` = 强制写回。）

### 2.7 读与写
- **Reading** = 把文件从磁盘装入 RAM（加载程序、打开文件）；
- **Writing** = 把 RAM 数据复制到外存。

## 3. 虚拟内存 Virtual Memory ⭐

- 思想与缓存**相反**：**用低层存储器（硬盘）"扩充"高层存储器（主存）**——把数据溢写到磁盘，相当于扩展了主存；
- 磁盘上保留的区域叫 **swap area（交换区）**；
- 例：物理内存 4 GB，虚拟内存上限 8 GB；
- 权衡：**灵活性提升，但比直接访问 RAM 慢**。

## 4. 云存储 Cloud Storage（了解）

- 数据存在不属于你的数据中心（网络访问）；背后是海量磁盘阵列、**多副本**；
- 每 GB 最便宜、延迟高不稳定 → 用缓存和 CDN 改善；适合备份、归档、大数据、静态内容。
